## 1. Что это технически

**Идея** `[ФАКТ: docs/adr/0011-the-workbench-is-a-constructor.md:7-9,35-43]`. Средняя колонка
консоли — холст карточек, который стал конструктором.

- Каждой карточке назначается **роль**: Object, Action, Decision, Event или Result.
- Каждой линии назначается **тип**: then, if, when, makes, with, а также `named` для эскизов.
- Шаги получают небольшой фиксированный набор полей, и весь рисунок можно **запустить**.
- Главное решение: *роль ≠ вид*. Вид (session, idea, blocker, file…) говорит, откуда карточка
  читается. Роль говорит, что она делает в процессе. Поэтому реальные объекты машины (сессии, идеи,
  PR, тикеты, файлы) становятся частью процесса, как только к ним провели линию.

### Модель данных (миграции 033–078)

Всё связано **по имени карточки `kind:id` (строка), а не внешними ключами** (`0011:67-69`).

| Таблица | Суть |
|---|---|
| `card_role` (033) | переопределённая роль; `roles.py:189-224` — естественная роль по виду |
| `card_tie` (034) | типизированная линия from→to, UNIQUE(from,to) |
| `card_field` (035) | поля роли: action `do/using/runs/asks`, decision `ask`, event `awaits`, result `counts` |
| `card_leave` (036) | разрешения шага: read/work/land/push/hands **обеспечиваются кодом**, `net` только **запрашивается** (`allowed.py:48-96`) |
| `card_made` (036) | **последний** результат карточки. Одно значение на карточку, общее для всех прогонов |
| `run` (037, 047, 049, 057) | прогон: замороженный список карточек, cwd, started/finished, stopped_why, paused_at, вложенность, входные данные |
| `run_step` (037, 058) | шаг: state `waiting/going/held/done/failed`, made, detail, usd, ms |
| `step_card`, `template*` (038, 048) | карточки «ещё ничего» и сохранённые рисунки (фигура, а не копия) |
| `bench_card`, `bench_was` (040–046) | расположение на верстаке отдельного чата; undo на 50 шагов одним JSON |
| `check_card`, `tool`, `button_card`, `asked`, `sketch_card` (059–078) | проверки, кнопки, вопросы человеку, рисунки проекта |

### Рендер

- **Клиентский.** `console.js` строит холст: абсолютно позиционированные «булавки», SVG-линии
  «локтем», drag & drop на pointer-событиях. Вся поверхность сохраняется POST-ом примерно через
  400 мс после изменения (`console.js:2405-2429` → `routes.py:2534-2584`).
- Тела карточек — серверные партиалы (`/cards/{kind}` → `_card_*.html`).
- Раскладка тремя способами: колонками по виду на клиенте, по линиям на сервере
  (`branching.lay_out`), статическая SVG-диаграмма на сервере. Есть экспорт в Mermaid
  (`diagrams.py`).
- Роль показывается формой, а не цветом: цвет зарезервирован для статуса (`0011:45-47`).
- Состояние прогона накладывается на карточки: метки `· ◐ ⏸ ✓ ✕`, полоса стоимости, панель прогона.
  **Опрос раз в 20 с**, не SSE (`console.js:4608`).

### Исполнение

- `process.py` — чистые функции: топологический порядок (цикл помечается как `tangled` и не
  запускается), «память» на один шаг, подсказки о пробелах, **сухой прогон без вызовов модели**.
- `web/engine.py` — цикл в `TaskGroup` приложения. Раз в 20 с он продвигает каждый прогон на один шаг.
  - **Action:**
    - с разрешением «только чтение» или как шаг-промпт — прямой вызов `claude -p`: веер по моделям,
      подстановка `{slot}`, учёт usd и ms;
    - с `runs=` — вложенный прогон;
    - с `hands` — ждёт человека;
    - иначе **ставит задачу** в очередь autostart. Сам движок агента не запускает, это проверяет
      AST-тест (`tests/unit/test_engine.py:46-62`).
  - **Decision:** модель выбирает пронумерованную ветку и объясняет выбор. Нет внятного ответа —
    шаг `held`, случайной ветки не бывает.
  - **Event:** срабатывает сам по закрытому списку условий (время, зелёный гейт, «ничего не
    бежит»). Иначе ждёт, пока человек нажмёт «это произошло».
  - **Проверки:** у Result-карточек есть `counts` в 4 машинных формах (contains, not contains,
    is json, shorter than N). Отдельная `check_card` помечает, кто судил: правило или модель.

- Загрузчик карточек продублирован в маршрутах и в движке (`routes.py:2674` и `engine.py:75`).

## 3. Чем он отличается от обычных визуализаций процессов

| | n8n / BPMN / LangGraph Studio / GH Actions / Temporal UI | Верстак |
|---|---|---|
| Узлы | интеграции, код, задачи | **реальные объекты на машине**: сессии, идеи, PR, файлы. Роль ортогональна виду |
| Авторство | холст плюс конфиг, или код | холст **или слова**: «нарисуй процесс» предлагает рисунок, человек принимает |
| Словарь | открытый или большой | **закрытый**: 5 ролей, 5 линий, без циклов, переменных и типов |
| Незаконченное | ошибка валидации | нормальное состояние; пробелы — подсказки; сухой прогон без модели |
| Исполнение | движок вызывает узлы | шаги исполняет LLM, агентов запускает только очередь с предохранителями |
| Ветвление | выражение над данными | выбор модели **с причиной**; нет ответа — держать |
| Проверки | assert в коде, статус CI | **проверка — это карточка** и говорит, судило правило или модель |
| Честность статуса | что сказал движок | нулевая стоимость означает «не измерено»; ожидание — `held`, а не `failed` |

Вывод `[ВЫВОД]`: большинство перечисленных инструментов *показывают* исполнения, определённые в
другом месте. Верстак, наоборот, — **поверхность для авторства со слабым исполнителем**. BPMN-lite
плюс стенд для промптов поверх собственной машины. Это действительно отличает его. Но при нуле
прогонов ценность исполнения не подтверждена, а ценность авторства подтверждена слабо.

## 4. Может ли он стать визуализацией прогонов ai-worker?

### Модель прогона ai-worker (в коде `staging@5b59158`)

- **Фазы** (`aiw:ai_worker/runtime/phases.py:16-67`): intake → clarify? → plan → implement →
  verify_local → push → review → correct? → verify_ci → report → sentinel → finalize. Отдельно есть
  watch-фазы и фазы автономной полосы.
- **Статус фазы:** pending/running/done/failed. Фаза считается done только при внешнем
  доказательстве, оно хранится в `run_phase.evidence`.
- **Статус прогона:** queued/running/interrupted/**waiting_for_input**/finished/failed/abandoned
  (`aiw:ai_worker/store/models.py:80-90`).
- **Вердикт Sentinel:** `sentinel_verdict` pass/repaired/fail, с JSON checks и discrepancies
  (`models.py:414-424`).
- **Вопросы:** таблица `question`, ответ даётся в Jira, возобновление по `ai:proceed`.
- **Расход:** в `usage` токены, **не доллары**.
- **Внешние поверхности:**
  - `GET /api/v1/projects/{slug}/runs`, `GET /api/v1/runs/{id}` с фазами, Sentinel и usage;
  - **SSE `GET /api/v1/runs/{id}/stream`** (`aiw:control/api/routers/runs.py:230-294`);
  - GET без авторизации, порт только на loopback (`compose.yaml:141-143`).
- **Собственная консоль** с «Run detail» и полосой фаз по SSE уже есть в коде
  (`aiw:control/console/views.py`).

### Что уже подходит

| ai-worker | верстак | соответствие |
|---|---|---|
| run | `run` | хорошее, если отобразить статусы |
| run_phase | `run_step` | хорошее: pending→waiting, running→going, done, failed |
| цепочка из 12 фаз | встроенный шаблон (`boxed.py`) | хорошее |
| clarify?/correct? как циклы | Decision + `if` | **плохое**: движок отказывается от циклов, раунды придётся разворачивать в отдельные прогоны |
| waiting_for_input, человеческие ворота | Event/`hands` → `held` | хорошее по смыслу |
| question | карточка `asked` | по форме подходит, но **отвечать в agent-desk нельзя**: ответ идёт через Jira |
| Sentinel | Result / `check_card` | частичное: нет `repaired`, нет списка расхождений, нет пометки «судил внешний Sentinel» |
| usage | `run_step.usd/ms` | частичное: колонки для токенов нет, доллары выдумывать нельзя |
| сравнение раундов | `comparing.py`, `spread.py` | хорошее |

### Чего не хватает

1. **Приём внешних прогонов.** Нужен модуль-парсер ответа API ai-worker с записанными фикстурами и
   проверкой версии (схема ADR 0004).
2. **Режим только для чтения.** Иначе `engine.tick` попробует исполнить импортированный прогон, а
   кнопки stop, pause и «это произошло» будут в него писать (`engine.py:430`, `routes.py:2873-2922`).
3. **Стабильные идентификаторы:** уникальный ключ `(source, external_id)` и детерминированные имена
   карточек фаз `aiw:<phase>`.
4. **Внешние статусы как есть** плюс `seen_at`. Статус прогона в agent-desk сейчас *выводится* из
   временных меток (`047:17-22`), для чужих данных так нельзя (правило №5).
5. **Живое обновление:** сейчас опрос раз в 20 с. Для начала этого достаточно.
6. **Новый ADR**, потому что `docs/01-vision.md:47-50` говорит, что agent-desk не должен
   выращивать аппарат ai-worker.

### Минимальный дизайн, если всё же делать

- Одна миграция: `run.source`, `external_id`, `external_status`, `url`, `seen_at`, уникальный
  индекс, а также `run_step.external_state`, `evidence`, `tokens`.
- Чистый читатель `agent_desk/observe/aiworker.py` над `GET /runs/{id}` с фикстурами. Цикл опроса
  раз в 30–60 с в `TaskGroup`.
- Один верстак на проект ai-worker со стабильными карточками фаз. Тогда существующие наложение,
  сравнение и разброс работают без изменений.
- Ограничители:
  - движок пропускает `source != ''`;
  - управляющие маршруты отвечают 409;
  - на вопросах нет кнопок ответа, только ссылка на комментарий в Jira;
  - токены показываются токенами.

Оценка: **15–20 ч** `[ДОПУЩЕНИЕ]`.

## 5. Вердикт

**Не делать верстак визуализацией ai-worker сейчас. Заморозить за флагом.** Причины:

- **Дублирование.** У ai-worker уже есть «Run detail» с полосой фаз и живым транскриптом. Второй
  рендер тех же данных — это поддержка двух UI над одной моделью, которая к тому же «не контракт»
  для agent-desk.
- **Данных нет.** ai-worker не развёрнут, сквозной прогон не подтверждён, коммитов нет с 09-10
  (`00_summary.md`, `07_open_questions.md` В1). Рендер пустоты не проверить.
- **Верстак сам не проверен в бою:** 0 прогонов. Строить интеграцию на непроверенном исполнителе —
  это два непроверенных слоя.
- **Цена:** клиентский JS без исполняемых тестов. Каждое изменение раскладки — риск, которого гейт
  не видит.

**Что делать вместо этого.** Полоса «ai-worker» на **доске**: HTML-строка на прогон. В ней проект,
тикет, текущая фаза, `waiting_for_input` как **факт**, вердикт Sentinel, «прочитано N с назад» и
ссылки в консоль ai-worker и Jira. Это 6–10 ч, и сюда же ложится тот же читатель
(`observe/aiworker.py`). Если через месяц окажется, что прогоны хочется *сравнивать по раундам*,
этот читатель без переделки кормит и верстак. Это единственная функция, которой у консоли
ai-worker нет, а у верстака есть (`comparing.py`).

**Когда пересмотреть:** ai-worker отработал ≥ 10 реальных прогонов, и есть конкретный вопрос,
на который его консоль не отвечает.
