# 01 · Суть проекта

## Проблема

Один разработчик запускает несколько агентов Claude Code параллельно. Агенты работают хорошо, а узким
местом становится человек: состояние работы видно только если смотреть в каждый терминал по
очереди, а работа идёт параллельно `[ФАКТ: docs/01-vision.md §The situation]`.

Вижн формулирует пять проверяемых проблем `[ФАКТ: docs/01-vision.md, таблица]`:

| # | Проблема | Критерий «решено» |
|---|---|---|
| 1 | Наблюдение за консолями — постоянная ручная работа | одна страница отвечает «что делает каждый агент» |
| 2 | Вопрос агенту о статусе его прерывает | ответ на (1) добавляет **ноль** байт в контекст агента |
| 3 | Идеи приходят посреди прогона и засоряют разговор | идея фиксируется < 10 с вне контекста агентов |
| 4 | Разработчик теряет нить | по каждой сессии видно последний запрос и последнее действие |
| 5 | Нетехнические коллеги хотят предлагать идеи | есть read-only редактированный вид |

Проблема 2 определяет архитектуру: **чтение бесплатно, запись стоит контекста** `[ФАКТ: docs/adr/0002]`.

## Целевая аудитория

- **Заявленная:** один разработчик на одной машине с несколькими параллельными сессиями Claude Code
  `[ФАКТ: docs/01-vision.md]`.
- **Фактическая:** сам автор. В базе один владелец, 4 выданных ссылки-просмотра, 1 группа проектов
  `[ФАКТ: агрегаты БД, таблицы viewer, project_group]`. Были ли внешние пользователи, неизвестно `[ПРОБЕЛ]`.
- **Потенциальная:** power-users агентных CLI (Claude Code, а при обобщении парсера также Codex CLI и
  Gemini CLI), тимлиды, у которых несколько агентов работают в worktree `[ВЫВОД]`.

## Ключевой сценарий

1. Разработчик держит консоль (`make overlay`) поверх рабочих окон.
2. Доска показывает сессии, отсортированные по триажу. Статусы `busy/idle/shell/waiting` взяты из
   реестра, а «может ждать вас» явно помечено как вывод из тишины `[ФАКТ: CLAUDE.md, правило 5; observe/model.py attention_hint]`.
3. Пришла мысль — одна строка в поле ввода. Классификатор определяет, вопрос это или идея. Вопрос
   уходит в `claude -p`, не блокируя поле, а идея попадает в инбокс `[ФАКТ: docs/04, docs/05]`.

## Ценностное предложение

> «Видишь всех своих агентов и записываешь мысли, не дёргая ни одного из них».

Отличие по сути — **принцип нулевого вмешательства**: ни один агент не узнаёт, что за ним наблюдают
`[ФАКТ: docs/adr/0002]`. Вокруг этого стоят жёсткие инварианты: не читать credentials, не писать в
наблюдаемый репозиторий, редактировать транскрипты на границе хранилища, не выдавать догадку за факт
`[ФАКТ: CLAUDE.md, «The five rules»]`. Инварианты проверяются тестами, в том числе через граф импортов
`[ФАКТ: tests/unit/test_security_surface.py]`.

## Две версии замысла: документ и реализация разошлись

| | Исходный замысел (docs/01, 08) | Реализация (`origin/main`) |
|---|---|---|
| Роль | «окно и блокнот» | окно, блокнот, оркестратор, конструктор процессов |
| Запуск агентов | «does not run agents, schedule them, assign them work» | `dispatch.py` запускает `claude --bg --worktree` по клику (ADR 0006) |
| Циклы | «нет правила, решающего хороший момент» | `autostart.py` и `kicking.py` каждые 30 с (ADR 0007, 0009), по умолчанию выключены |
| Самостоятельная работа | отвергнута в ADR 0007 | «агент находит себе работу» (ADR 0008) |
| Трекеры | non-goal §8: «No tracker» | запись в Jira (0005), чтение Jira и GitHub (0010), `tracker/` |
| Интерфейс | серверный HTMX, «никакой сборки JS» | сборки нет, но есть `console.js` на 7262 строки, а верстак — canvas-подобный конструктор (ADR 0011) |
| Закрытие сессий | «no button that starts, stops, or steers» | автоматическое закрытие сессии при 4 условиях (ADR 0012, `tidying.py`) |

Каждый шаг расширения оформлен ADR с аргументацией. Это аккуратно, но суммарно продукт сменил
категорию: был «наблюдатель», стал «локальный пульт управления агентами» `[ВЫВОД, уверенность высокая]`.

## Аналоги и альтернативы

> ⚠ Оценка по знаниям модели, **без актуального исследования рынка**. Названия и возможности нужно
> проверить перед любыми решениями.

| Аналог | Что делает | Отличие agent-desk |
|---|---|---|
| Нативный Claude Code: `claude --bg`, `claude agents`, `/tasks`, веб-версия claude.ai/code | запуск и список фоновых сессий | agent-desk видит **все** сессии машины, включая интерактивные, плюс инбокс идей; но натив может это поглотить |
| Conductor (macOS) | параллельные агенты Claude Code в worktree с UI | Conductor — оркестратор, agent-desk исходно наблюдатель |
| Crystal / ccmanager / claude-squad | менеджеры нескольких сессий в worktree/tmux | те запускают и управляют, agent-desk читает без вмешательства |
| Vibe Kanban | канбан-доска задач для кодинг-агентов | ближе к текущей (раздутой) версии agent-desk |
| opcode (бывш. Claudia), ccusage | GUI и аналитика по сессиям и расходам | аналитика без live-доски и без инбокса |

**Уникальное, что остаётся:** read-only доска по всем сессиям машины без вмешательства, инбокс идей
вне контекста агентов, честная маркировка догадок. **Неуникальное:** всё, что добавлено после
ADR 0006 (запуск, оркестрация, канбан), у конкурентов уже есть `[ВЫВОД, уверенность средняя]`.

## Монетизация

- **Заявленная:** нет. Проект описан как локальный однопользовательский инструмент: «no tickets, no
  clients, no multi-tenancy» `[ФАКТ: CLAUDE.md §2]`.
- **Возможные** (подробно в `06_value_assessment.md`):
  - open-source и репутация: GitHub, статьи, доклады. Реалистично.
  - платная десктоп-сборка или «Pro» для команд с общим видом. Слабо: платформенный риск и сильные бесплатные аналоги.
  - спонсорство (GitHub Sponsors). Копейки, но почти бесплатно.
  - консалтинг и обучение по «дисциплине агентной разработки», где проект служит витриной. Самый реалистичный путь к деньгам `[ВЫВОД]`.
