# 04 · Путь до MVP и релиза

Допущения: соло, **~10 ч/неделю**, работа с агентами Claude Code, бюджет — подписка Claude
`[ДОПУЩЕНИЕ, см. 07_open_questions.md В3]`. Оценки ниже даны в часах человека. Агенты ускоряют
написание кода, но не ревью, решения и проверку ценности.

## Определение MVP

**MVP = «доска + инбокс» для одного разработчика на чужой машине.** Человек, который не видел
проект, ставит его за 5 минут и в тот же день перестаёт ходить по терминалам, чтобы узнать статус
агентов.

### Входит

1. Доска: все сессии Claude Code на машине, группировка проект → инстанс → сессия, факты реестра
   отдельно от выводов, хвост транскрипта по клику (`observe/`, `web/sse.py`).
2. Флаг «может ждать вас», честно помеченный как вывод (story 04 уже починена).
3. Поле ввода: идея попадает в инбокс; вопрос уходит в `claude -p` без блокировки (`answer/`, `ideas/inbox.py`).
4. Инбокс: keep/discard, черновик, «сделано».
5. Overlay-окно (`make overlay`).
6. Предупреждение о версии CLI (уже есть).
7. Установка одной командой (`pipx install` или `uvx`), LICENSE, README для постороннего.

### Сознательно НЕ входит (выключено флагом или вынесено)

- Запуск агентов, `land`, autostart, kicking, tidying (ADR 0006–0009, 0012).
- Верстак-конструктор, процессы, прогоны, инструменты (ADR 0011, docs/12).
- Jira и GitHub, MCP-сервер, shared-вид для коллег, встречи.
- Запись в работающую сессию (`peer.py`: клиента CLI по-прежнему нет).

Всё это остаётся в коде. Если будет доказан спрос, это первые кандидаты в «Pro» или на релиз.

## Критерии готовности MVP (проверяемые)

| # | Критерий | Как проверить |
|---|---|---|
| K1 | `pipx install` из git-URL, `agent-desk` открывает доску на чистой машине с Claude Code | чистый контейнер или VM, запись шагов |
| K2 | Полный рабочий день автора с ≥3 сессиями без открытия терминала ради статуса | журнал дня; число «ушёл в терминал» ≤ 2 |
| K3 | Идея записывается ≤ 10 с и через неделю видно, что происходило вокруг неё | секундомер; повторный просмотр через 7 дней |
| K4 | 3 внешних разработчика поставили и пользовались ≥ 3 дня | их короткие отзывы |
| K5 | `make verify` зелёный в CI; быстрый гейт < 60 с | GitHub Actions |
| K6 | Фикстуры записаны на актуальной версии CLI | `RECORDED_CLI_VERSION` = установленная |
| K7 | В README нет утверждений, противоречащих коду | ревью по таблице расхождений из 02 |
| K8 | С конфигурацией по умолчанию ни один агент не запускается и ни один вызов модели не делается без ввода пользователя | тест: при старте нет subprocess `claude` |

## Критический путь

```
0.1 → 0.2 → 0.3 → 1.1 → 2.1 → 2.2 (день доски) → [решение 2.4] → 3.1 → 3.2 → 3.3 → 4.x
```

Главный блокер — **2.2**. Всё после него имеет смысл только при положительном результате, поэтому
он стоит раньше упаковки.

## После релиза

- Возврат «лабораторных» функций по одной, каждая по доказанному спросу: запуск агента по клику → очередь → трекеры.
- Адаптеры для других CLI (Codex CLI, Gemini CLI) через тот же паттерн «один парсер + фикстуры + версия».
- Shared-вид с TLS для команды.
- Запись в сессию (`peer.py`), когда появится официальный клиент.
- Meeting intake v2/v3 (docs/10) — только при появлении пользователя.
