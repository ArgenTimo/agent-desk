## Суть

**agent-desk** — локальная веб-консоль для разработчика, у которого параллельно работают несколько
сессий Claude Code. Консоль читает `~/.claude/` и показывает, кто чем занят и кто ждёт человека, не
добавляя ни байта в контекст агентов. Ещё в ней есть инбокс идей, которые не тратят ничей контекст
`[ФАКТ: README.md, docs/01-vision.md]`.

За две недели проект вырос далеко за исходный замысел. Теперь он умеет запускать фоновых агентов,
будить простаивающие сессии, читать и писать в Jira и GitHub, работает MCP-сервером и содержит
визуальный конструктор процессов («верстак») `[ФАКТ: docs/adr/0006–0012, docs/12-the-tool-builder.md]`.

## Стадия

**Работающий прототип / pre-MVP как личный инструмент.** Автор пользуется им сам на реальных данных,
но публичного MVP нет.

- Автор реально пользовался консолью: 503 идеи, 121 вопрос-блок, 25 запущенных задач, $24.81
  расходов на модели учтено `[ФАКТ: агрегаты из ~/.local/share/agent-desk/agent-desk.db, только count/sum]`.
- Ни один критерий «done-when» из roadmap не отмечен выполненным. README сам пишет: «Phases 1 and 2
  are built. Neither is done» `[ФАКТ: README.md §Status, docs/09-roadmap.md]`.
- Нет лицензии, CI, упаковки для чужой машины и ни одного внешнего пользователя `[ФАКТ: нет LICENSE, нет .github/; ВЫВОД]`.

| Проверка ценности (день без терминала) | 0 % | нигде не зафиксирована `[ПРОБЕЛ]` |
| Готовность для чужой машины (лицензия, установка, онбординг) | ~20 % | `[ФАКТ: нет LICENSE; pyproject version 0.0.0]` |

Код MVP почти готов. Оставшиеся 30 % — это не код, а наведение порядка, проверка ценности и упаковка.
Уверенность: **средняя**, потому что процент зависит от того, кого считать пользователем MVP (`07_open_questions.md`, В1).

## Топ-5 проблем

1. **Неконтролируемое расползание объёма.** Вижн прямо говорит «не запускает агентов и ничего не
   решает», а ADR 0006→0012 за 5 дней по шагу отменили почти все non-goals. Появились оркестрация,
   автономные агенты, трекеры, MCP и конструктор. `CLAUDE.md` сам называет это главной угрозой
   («the pull toward turning this into a second ai-worker… must be resisted») `[ФАКТ]`. Уверенность высокая.
2. **Долг слияния.** 20 PR в статусе draft/open, 40+ локальных веток, 30+ worktree, 4 worktree с
   незакоммиченной работой, локальный `main` на 89 коммитов позади `[ФАКТ: gh pr list, git worktree list]`.
   Состояние проекта трудно даже определить.
3. **Ценность ядра так и не проверена.** «Полный рабочий день без открытия терминала» ни разу не
   проведён. Консолью для вопросов перестали пользоваться после 2026-09-10, идеи последний раз
   записаны 2026-09-16 `[ФАКТ: даты в БД]`.
4. **Монолиты.** `web/routes.py` 5768 строк и 150 маршрутов, `store/repo.py` 4951, `web/blocks.py`
   2389, самописный `console.js` 7262 строки, 78 миграций за 14 дней `[ФАКТ: wc -l]`. Тезис «HTMX и
   никакого JS» по факту не выдержан.
5. **Сильная зависимость от внутреннего формата Claude Code и от Anthropic.** Форматы `~/.claude/` не
   являются контрактом (ADR 0004). Нативные `claude --bg` и `claude agents` уже закрывают часть
   сценариев, и платформа может сделать доску сама `[ВЫВОД]`.

## Объём работ до MVP

При допущении **соло, ~10 ч/неделю, бюджет ≈ подписка Claude** `[ДОПУЩЕНИЕ]`: **4–6 недель** до MVP для
внешнего пользователя (детали в `04_roadmap.md`). До «MVP для себя» — **1–2 недели**, почти целиком
уборка и проверка ценности.

## Вердикт: **переосмыслить → сузить до ядра и довести его до MVP, параллельно оформить как кейс**

Почему не «довести до MVP как есть». Текущий объём — это оркестратор, конструктор процессов,
MCP-сервер и интеграции с трекерами. Для соло-разработчика с ~10 ч/неделю это неподъёмно в
поддержке, тем более на формате, который не является контрактом (`03_problems_and_risks.md`, R1–R3).

Почему не «заморозить». Ядро (доска + инбокс) работает, покрыто тестами, решает реальную и
растущую проблему многоагентной работы, и автор им пользовался. Инженерная дисциплина проекта
(ADR, фикстуры с версией CLI, тесты на инварианты безопасности) сама по себе ценный кейс
(`06_value_assessment.md`).

Что делать конкретно:

1. Разобрать долг слияния.
2. Выключить по умолчанию всё, что после ADR 0006.
3. Провести один честный «день доски».
4. Упаковать ядро для чужой машины.

Если день доски провалится, проект переходит в «оформить как кейс», и это нормальный исход.
Уверенность в вердикте: **средняя**. Она сильнее всего зависит от цели проекта, которую владелец не указал.
